# 天保郷帳 石高マップ

**https://yuta1984.github.io/tempo-gocho-viewer/**

天保年間（1834–44）の郷帳に記された全国 54,948 村の石高を、同時代の地図
「[れきちず](https://rekichizu.jp/)」の上に重ねて見るビューア。

れきちずが描くのは江戸後期（1800〜1840年ごろ）なので、**ベースマップと資料の年代がほぼ一致する**。

## 見え方

- **広い範囲**（〜z9.5）… 石高で重み付けしたヒートマップ。穀倉地帯の分布が見える
- **寄ったとき**（z10.5〜）… 村ごとの円。**面積が石高に比例**し、色は6階級
- z9.5〜10.5 でクロスフェードする。村は平均2.4km間隔で、z10 が「村が個体として分離して見え始める」境界

石高の階級は 100 / 250 / 500 / 1000 / 2000 石。分位点に近い切りのよい値にしてある
（生の分位点では 156.4石 のような半端な境界になり、石高を読む側にとって意味がない）。
実際の分布は 15% / 24% / 27% / 23% / 9% / 2% で、下位から中位が均等に割れる。

色は暖色系。れきちずの地色が淡い緑の陸と水色の海なので、青系・緑系では沈んで見えない。

URLの `#ズーム/緯度/経度` で表示位置を指定・共有できる（例:
[`#12/36.06/136.22`](https://yuta1984.github.io/tempo-gocho-viewer/#12/36.06/136.22) で福井付近）。

## 確定と要確認

村ごとの名寄せ結果には、人手の確認を省いてよい「確定」と、確認が要る「要確認」の別がある。
判定は本体側の `geocode.js` が行い、その結果をこのビューアが受け取る。

- **確定**（47,126村）… 候補が1件で信頼度が高い村、または次点候補を大きく引き離した村
- **要確認**（8,222村）… それ以外。地図では**薄く**表示され、絞り込みで抜き出せる

正解データ4冊（2,553行）で測ると、確定に混入する誤りは0.75%だった。

## 絞り込みと検証

国（83冊）・郡・**確認状態**・石高の下限・信頼度の下限で絞り込める。国を切り替えるとその範囲に地図が寄る。

村をクリックすると、郡・国・石高・現在地名・GeoLOD_ID・一致方法・信頼度・次点差と、
みんなで翻刻の該当コマ／『日本歴史地名大系』の項目へのリンクが出る。
次点差が負のときは、記載順の制約から最高得点でない候補を採ったことを意味する。

このデータの村と地名辞書の対応づけ（名寄せ）は自動処理で、人手による検証済みの
1冊（越前国郷帳 722行）で測った精度は **正答 90.3% / 誤り 1.9%** である。
そのため次の2点を画面に出している。

- **要確認の村は薄く**表示する。隠すのではなく、確かでないことが見えるようにしている
- 統計バーに**座標が付かなかった村の数**（全国5,654村）を出す。黙って落とすと石高が実態より少ないことに気づけない

「『日本歴史地名大系』の地名」をONにすると、れきちず側が持つ地名ラベルが出る。
名寄せが合っていれば郷帳の村がこのラベルに重なるので、目視の検証に使える。

## 開発

```bash
npm install
npm run dev
```

Node は 20.19+ または 22.12+。

`public/data/points.json` と `meta.json` は
[天保郷帳データセット](https://github.com/yuta1984/tempo_gocho)のTSVから生成したもので、
生成スクリプトは本体側のリポジトリにある（`scripts/tempo/build-viewer-data.js`）。

`main` に push すると GitHub Actions がビルドして Pages に反映する。

### 構成

| パス | 役割 |
|---|---|
| `src/App.tsx` | 状態の集約（読み込み・フィルタ・選択中の村） |
| `src/components/MapView.tsx` | MapLibre の生成と source/layer の管理 |
| `src/lib/layers.ts` | heatmap / circle / label のレイヤ定義と配色 |
| `src/lib/filter.ts` | 絞り込み・GeoJSON化・集計（同じ1パスで行う） |
| `src/lib/data.ts` | `public/data/*.json` の読み込み |
| `src/lib/format.ts` | 表示書式と外部URLの組み立て |

**MapLibre と React の境界**: 地図インスタンスは `useRef` に置き state には入れない。
`map.on('load')` で立てる `ready` だけが再レンダーを起こす。
ソースとレイヤの追加は1回だけのエフェクト、データ更新は別のエフェクトに分ける
（同じエフェクトに混ぜると絞り込みのたびにレイヤが作り直される）。
StrictMode の二重実行は生成を止めるガードではなく、cleanup の `map.remove()` で対処する。

絞り込みは MapLibre の `setFilter` 式ではなく **JS側で配列を絞って `setData`** する。
表示中の村数と石高合計をどのみち JS 側で数える必要があり、同じ走査でまとめられるため。
式と JS の二重定義にすると、パネルの数字と地図の見た目がズレるバグを構造的に抱える。
